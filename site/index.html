Your Mac was never meant to be a cargo ship.

Crateyard runs Docker in a small Linux VM that gives memory back to macOS when your containers go quiet. Same docker commands. Open source.

LOAD MARKS

Light when idle. Loaded only when you are.

A Mac is a laptop first. Crateyard treats memory and disk as things it borrows, and hands them back.

SAME DOCKER

Nothing to relearn.

Crateyard runs the real dockerd, unchanged, and points your docker CLI at it while it runs. Your compose files and scripts keep working.

GET STARTED

One line, then press Start.

  1. curl -fsSL https://raw.githubusercontent.com/Malaydewangan09/crateyard/main/install.sh | shinstalls Crateyard.app
  2. open -a Crateyardbuilds the VM once, a few minutes, then press Start
  3. docker run hello-worldCrateyard has already switched your docker context

The script checks the download against its published SHA-256 before installing. Rather build it yourself? Clone the repo and run ./app/scripts/bundle.sh.

HONEST LIMITS

  • Work in progress. Memory used while containers run comes back only when the VM sleeps.
  • Docker Desktop checks the active docker context every few seconds, so Crateyard cannot sleep while it is open.
  • Apple silicon only. TCP ports only, no UDP yet.
  • Crateyard runs the engine, not the docker command. Without Docker Desktop, get it with brew install docker docker-compose.
  • Not notarized by Apple. The install script avoids the Gatekeeper prompt, a downloaded DMG needs Open Anyway.
  • No Kubernetes, and it is not trying to be Docker Desktop.
